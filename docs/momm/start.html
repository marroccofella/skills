Before you start

You need Git, Node.js 18 or newer, an Agent Skills-compatible harness and an account session for at least one external reviewer. Provider subscriptions, quotas and availability still apply.

Recommended: let your agent verify the release first

Copy the new-user / upgrade prompt →

A clone starts on the default branch, which can contain unreleased work. Before executing the manual installer below, select the published signed release, verify its expected signing identity and package hash, and read its installer help. The copyable prompt covers those steps and asks before installing missing prerequisites.

01 Verify, then install only MOMM

Use the new-install and legacy bootstrap guide to prepare an exact signed release in a permanent directory before executing its code. The separately trusted bootstrap helper checks tools first and never installs or replaces an existing link. Keep the verified clone: your harness will link to it.

Missing verifier is not a bad signature

Ask before installing gitsign; on macOS with Homebrew, its official command is brew install gitsign. GitHub’s bad_cert / Unverified badge is not a gitsign result. Verify the expected signer, transparency record and package hash; stop on any actual failure.

1. Preview only
node momm/scripts/install.mjs --target codex --dry-run

Read the preview before choosing to run the separate installation command:

2. Install only after approving the preview
node momm/scripts/install.mjs --target codex

Restart or refresh your agent’s skill discovery if needed. --target all is an explicit multi-harness choice; root install.mjs installs the whole collection.

The installer records the successful harnesses and their exact skill scopes in momm.lock under Git’s local MOMM state directory. It never overwrites existing discovery paths.

02 Connect a reviewer

From the skills clone, open the local Setup Center:

Open Setup Center
node momm/scripts/setup-ui.mjs

Choose your current agent as governor. Use the provider’s login action and complete the browser login yourself. Quick Setup can test detected sessions with a disclosed synthetic sentence—not your project source.

The page opens on a local, automatically chosen port. In a headless session, use node momm/scripts/onboard.mjs --governor codex. Installed credentials are evidence, not a promise that the next dispatch will succeed.

03 Review the right project

Open the project you want reviewed in your agent. Paste this:

Paste into your agent
Use $momm to review my current changes. Keep this project as the working directory. Use at least one ready external reviewer, reproduce material findings before authoring fixes, record every suggestion’s disposition, and show me the private ledger link.
Prefer the terminal? Codex on macOS / Linux
Run from your project
node "$HOME/.agents/skills/momm/scripts/multi-review.mjs" --preflight --governor codex --pretty
node "$HOME/.agents/skills/momm/scripts/multi-review.mjs" --governor codex --min-success 1 --pretty
Codex on Windows / PowerShell
Run from your project
node "$env:USERPROFILE/.agents/skills/momm/scripts/multi-review.mjs" --preflight --governor codex --pretty
node "$env:USERPROFILE/.agents/skills/momm/scripts/multi-review.mjs" --governor codex --min-success 1 --pretty
Working directory matters

Without redirected input or --input, MOMM reviews git diff HEAD in the current directory. Running it from the skills clone reviews the skills—not your project. For another harness, use its installed skill path and its actual governor name.

04 Close the loop

Reviewer replies are only the first half. The governor investigates material findings, authors any supported fixes, tests them, and records every suggestion as applied, rejected or deferred with a reason.

Applied decisions need checkable evidence: a regression test, a commit or a concrete probe. A deferred item is still open work. Run node <installed-momm>/scripts/governor.mjs --run <run_id> from the project. It matches stable item IDs to decisions and verifies original report/input binding and recorded source, test and output hashes. Missing, duplicate, deferred or stale evidence stays incomplete. Add --record only after checks pass; this saves a separate receipt and rebuilds the private ledger. The validator never executes reviewer snippets and cannot independently prove an observation was honestly recorded or a test adequate.

Your agent appends decisions to your project’s .ensemble_reviews/dispositions.jsonl, joined to the report’s run_id. Zero dispositions can mean no suggestions existed—or an unfinished review. Check the actual report.

05 Open your private dashboard

The agent should relay the ledger link after every completed run. To rebuild it yourself after adding decisions, run this from the same project:

macOS / Linux · Codex
node "$HOME/.agents/skills/momm/scripts/ledger.mjs" --open
PowerShell · Codex
node "$env:USERPROFILE/.agents/skills/momm/scripts/ledger.mjs" --open

This opens the local .ensemble_reviews/ledger.html. It is not the public evidence website. Keep the evidence directory private and out of temporary folders.
