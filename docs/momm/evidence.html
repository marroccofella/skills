What could improve for you—and what we have measured

MOMM adds an explicit challenge-and-verification step to AI-assisted work. The practical benefits to look for are additional defects identified, unsupported suggestions rejected, and a review history you can inspect. Their size depends on your tasks, reviewers and the governor’s tests.

Potential benefitObservation in this development snapshotWhat it does not establish
Find changes worth making302 recorded applied decisions; the linked supervisor case includes a named regression test.Not 302 unique bugs, independently verified fixes or a user defect-reduction percentage.
Filter unsupported advice251 recorded rejected decisions; a rejected CRITICAL claim remains inspectable.Not a measured false-positive rate or a guarantee that the governor always rules correctly.
Keep an inspectable decision trail570 decision records across 153 logged runs; 139 detailed stored reports. 8 decisions are deferred and 9 retain historical labels.Not a count of users, deployments, commercial outcomes or independent replications.

No controlled AI-alone versus AI-plus-MOMM comparison is included in this snapshot. It cannot establish an average accuracy gain, time saving, cost saving or return on investment. The timing charts measure reviewer responses, not end-to-end developer productivity. Adding reviewers can add time and provider cost.

Measure the benefit on your own work

Use a held-out set of representative tasks and a pre-defined test oracle. Compare the same base model and settings with and without MOMM, vary run order, and repeat trials. Include failed routes, total elapsed time, provider costs, confirmed defects and regressions introduced. Report the sample size, uncertainty and evaluation method before claiming a general improvement.

Which bytes does a hash cover?

Snapshot sidecar
The exact downloaded momm-evidence.json bytes. You can recompute this locally.
stored_report_sha256
Original private report bytes before sanitization. Provenance only; it cannot validate the altered public object.
public_report_sha256
The sanitized report serialized as compact UTF-8 JSON with recursively sorted object keys; array order is retained. The renderer and CI recompute every one.
Executable hashes
New reports identify the actual installed dispatcher, updater and protocol file bytes. A version string alone is not evidence that two executions used identical code.

How this page stays in sync

One offline renderer reads the committed public snapshot and generates this page, its tables and downloadable data. CI compares the regenerated outputs byte for byte, checks the ledger’s embedded data, and verifies the public hashes. Refreshing the site does not import private ledgers or change the snapshot’s date.
