Why MOMM exists

The gap: agents grading their own homework.

Every AI coding agent reviews its own output with the same model that wrote it — same blind spots in, same blind spots out. Cross-model review existed only as copy-paste between chat windows: no protocol, no evidence, and a pocketful of API keys you pay for twice. MOMM closes that gap: the models you already subscribe to become a standing peer-review coalition, with an integrity protocol machines actually follow.

Look closely at today's AI coding harnesses and the weakness is structural, not incidental. The model that writes a change also judges it — and models measurably prefer their own output, so the judge is biased by construction. There is no adversarial pass: nothing in the loop is rewarded for finding what the writer missed. Review artifacts live in scrollback — when the session ends, the reasoning evaporates, unauditable. And when teams do wire up second opinions, it's pay-per-token API keys duct-taped through environment variables, running beside the agent instead of inside its own gated workflow. MOMM turns each weakness into a rule: a governor that cannot grade its own homework, rival models with nothing to protect, findings that are claims until reproduced, and every word sealed under a hash — using only the OAuth subscriptions already on the machine.

◇Monoculture risk

One model family means correlated failures. MOMM's proof case: a NaN bug froze every ghost in a game on level 1 — the author's own green test suite missed it; a rival model caught it in one pass.

◇Self-certification

An agent that writes, reviews, and approves is a rubber stamp. MOMM's governor self-excludes, and reviewers can't write — separation of powers, enforced in code.

◇Key sprawl

Pay-per-token API keys for models you already subscribe to, scattered through env vars. MOMM strips every known key variable and rides official OAuth logins only.

◇Vanishing reviews

Chat-window reviews evaporate. MOMM seals every conversation content-addressed, binds it to the exact input hash, and answers every suggestion on the record.

The architecture

How a review flows.

Under the hood

One file. Zero dependencies. Nowhere to hide.

The dispatcher is a single Node 18+ script — no packages, no lockfile, fully auditable in one sitting. Two of its load-bearing ideas:

◈Termination-proof containment

Every reviewer subprocess runs inside a layered kill chain — process-tree kill → child-kill backstop → referenced hard deadline → explicit flush-then-exit — so even a kill-restricted sandbox always gets its structured report back. Every adapter must route through it; the protocol forbids simplifying it.

◈Fail-closed identity

Reviewer subprocesses receive an environment scrubbed of every known API-key variable (OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, XAI_API_KEY…). A route without an official OAuth session cannot silently fall back — it returns a status with its exact login command.

Verified by 27 deterministic self-tests plus a CI matrix across 3 operating systems × 3 Node versions on every push — including forced-failure drills for evidence persistence and stream purity. Requirements: Node.js 18+; on Windows, run from a context permitted to terminate its own process tree (the containment chain uses taskkill /T) — restricted sandboxes are the documented exception. The coalition

Five minds. One gate. No blind trust.

Reviewers are read-only diagnostic instruments — their output is evidence, never instructions. The governor (your agent) self-excludes from reviewing its own work, and no finding is acted on by vote: it must be reproduced first.

Every route uses its provider's official CLI and browser login — including Grok via xAI's official CLI, adapter live-verified in the sealed ledger. Why “modality”? Each model family is treated as a distinct modality of judgment over the same artifact — and the roadmap extends to literal modalities: visual review of rendered UIs and structural review over ASTs are the planned sibling skills.

Evidence, not vibes

Every claim resolves to a hash.

Reports are content-addressed (sha256 over stored bytes) and bound to the exact reviewed input by its own hash. Every reviewer suggestion gets an explicit applied-or-rejected disposition with named evidence. Release gates can demand a quorum — timeouts cannot silently thin the coalition. And MOMM eats its own cooking: every version of MOMM was reviewed by MOMM, and the sealed ledger is public.

The numbers live in one place — the Measured, not marketed section above, computed from the ledger itself. Browse the raw material: the public evidence ledger — who said what, what was applied, what was rejected and why.

Get started

Three commands to a five-model review.

  1. Clone and link into every detected harness (Claude Code, Codex, Gemini, Antigravity — junctions on Windows, symlinks elsewhere):

    git clone https://github.com/marroccofella/skills && node skills/momm/scripts/install.mjs --target all

  2. Check every route — zero model calls; prints the exact install/login command for anything that’s down:

    node skills/momm/scripts/multi-review.mjs --preflight --pretty

  3. Review your changes (or just tell your agent “use momm”). Your private dashboard is one more command: node skills/momm/scripts/ledger.mjs --open

    git diff HEAD | node skills/momm/scripts/multi-review.mjs --governor claude --pretty

Repository conventions: drop a .reviewrules file at your repo root (style constraints, review priorities, forbidden patterns) — it is injected into every reviewer's prompt, and the report confirms it was applied. Release gates: add --min-success N to fail loudly if timeouts thin the coalition below quorum.
