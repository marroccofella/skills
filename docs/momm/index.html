Why use MOMM?

Overview and evidence

One agent writes. Others challenge it. You keep the evidence. MOMM gives your coding agent independent review claims from the provider tools you already use. The benefit is a checkable decision trail, not a guarantee that a group of models is right. This tour shows the actual interfaces, with screen actions accelerated fifteen times and narration at normal speed.

The current release

Release notes and update controls

The current stable release shown here is 1.15.1. It keeps the new explicit updater, separate approval for protocol changes, installation receipts, and source linked governor checks. This patch fixes signed update staging. Its public release workflow tested a genuine signed preview and installation. The page links the exact release and test run. A signature proves provenance, not correctness.

Install or upgrade deliberately

Installation guide and copyable prompt

New user? Open Get started. Keep the skills clone in a permanent folder, choose your harness, and inspect the installation preview before applying it. Existing user? Copy the upgrade prompt. Your agent checks the newest stable release and preserves your login sessions, other skills, and private ledgers. Older installations may need the verified bootstrap described in the guide. Never confuse a draft branch with a release. Review every protocol change before accepting it.

Your Setup Center

Live local Setup Center

The Setup Center is for connecting and maintaining reviewer tools. See the installed versions, choose your governor, and check the routes you intend to use. Latest version checks and updates are separate actions. Installing a tool does not prove its account can review. Quotas, network access and login storage can still block it. Browser login stays yours to complete. No secret keys are needed.

Finish the review loop

Review instructions and governor checks

Run the review from your project, using the installed skill path. Approve the providers before sharing code. The governor does not review itself. Peer findings are claims. Your agent investigates material findings, writes any supported fix, runs tests, and records a decision for every suggestion. Deferred means still open. A completed review needs the governor's evidence checks, not just positive votes or a matching decision count.

Open the evidence ledger

Sanitized public ledger and charts

The ledger answers who said what and what happened next. This public example is a sanitized historical snapshot, not your private dashboard. It contains 153 runs, 139 stored reports, and 570 decisions. Charts show timing, verdicts and failures with their denominators. Applied decisions are the developer's judgments, not independently measured accuracy. Current release checks are shown separately.

Start small. Keep the proof.

Installation prompt and limits

MOMM also reviews prose, and selected routes support images or other attachments. Capability depends on the actual tool, not the logo. Start with a small approved project and one available external reviewer. Keep your tests, close the decisions, and save the ledger somewhere permanent. Use the current release link on the page for later updates. Nothing installs or updates automatically.

KNOW THE BOUNDARY

Local control. External reviewers.

The selected providers receive your sanitized review input through their CLIs. Redaction reduces risk; it does not guarantee that confidential information is gone. Use MOMM only when sharing that material with those providers is allowed.

The daily notice requests a public version manifest. It never downloads code. Disable it with NO_UPDATE_CHECK=1 or DO_NOT_TRACK=1.
