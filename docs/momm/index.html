Your agent dispatches a diff, a document, or attached media to the other installed LLM CLIs — OpenAI Codex, Claude Code, Google Antigravity, GitHub Copilot, xAI Grok — which review it in parallel and return structured, deduplicated findings. Why MOMM exists

The gap: agents grading their own homework.

Every AI coding agent reviews its own output with the model that wrote it — same blind spots in, same blind spots out. Models measurably prefer their own output, so the judge is biased by construction; nothing in the loop is rewarded for finding what the writer missed; the reasoning lives in scrollback and evaporates with the session; and a second opinion usually means pay-per-token API keys duct-taped through environment variables. MOMM turns each weakness into a rule: a governor that cannot grade its own homework, rival models with nothing to protect, findings that are claims until reproduced, and every word sealed under a hash — using only the OAuth subscriptions already on the machine.

◇Monoculture risk

One model family means correlated failures. Proof case: a NaN bug froze every ghost in a game on level 1 — the author's own green test suite missed it; a rival model caught it in one pass.

◇Self-certification

An agent that writes, reviews, and approves is a rubber stamp. MOMM's governor self-excludes, and reviewers can't write — separation of powers, enforced in code.

◇Key sprawl

Pay-per-token keys for models you already subscribe to, scattered through env vars. MOMM strips every known key variable and rides official OAuth logins only.

◇Vanishing reviews

Chat-window reviews evaporate. MOMM seals every conversation content-addressed, binds it to the exact input hash, and answers every suggestion on the record.

Precision = suggestions the governor applied ÷ (applied + rejected), as triaged after reproduction. It is an attention prior only: the dispatcher ranks routes by it (investigation_order) and flags single-source findings from low-precision routes verify_first, but every material finding is still reproduced before it is believed. Timeouts scale with input size, which is why the dispatcher scales its budget with bytes and honours an explicit --timeout above the cap.

Peer review & scientific publishing

The same protocol is editorial peer review — with the paperwork done for you.

Strip away the code and MOMM is an editorial workflow: an author submits an artifact; several referees with different training read it independently and in parallel under the journal's reviewer guidelines; an editor who did not write the paper weighs the reports, checks the claims that matter, and records a decision with reasons; and the whole exchange is kept as an auditable record. Every one of those has a first-class counterpart below.

◈Manuscripts & preprints

Statistical validity, claims-versus-evidence, internal consistency, reproducibility — with your own guidelines in .reviewrules. Referee a draft before submission; referee a submission before the editor does.

◈Figures, PDFs, slides

--attach images and PDFs to vision-capable routes (Codex, Claude, Gemini). Metadata is stripped locally before anything leaves the machine; the report records only name, modality, bytes and sha256.

◈Grant proposals & policy

Ask the adversary persona to attack the plan, the fresh-eyes persona to find what a panel member would trip over, the innovator to propose the experiment you have not thought of — each in its own lane, none allowed to edit.

◈Code, still

Diffs, patches, whole files. Timeouts scale with size; quorum gates (--min-success) stop a thinned coalition from passing a release; the private ledger keeps every run beside the repo.

◈Reproducible decisions

Every verdict resolves to a hash and every suggestion to a disposition with a reason. A reviewer that was wrong is rejected on the record — and its precision falls in the next run's investigation_order.

◈Teaching & assessment

Have students' work refereed by five independent readers under a rubric file, then grade the referees against the rubric. The ledger's track record is the exercise.

  1. Put your guidelines beside the artifact — the dispatcher injects them into every referee's prompt and the report confirms it:

    printf 'Priorities: statistical validity, claims vs evidence, reproducibility.\nCRITICAL = invalidates a headline conclusion.' > .reviewrules

  2. Referee a manuscript (text) or attach a PDF/figure for the vision-capable routes:

    node skills/momm/scripts/multi-review.mjs --governor claude --input paper.md --label "manuscript v3" node skills/momm/scripts/multi-review.mjs --governor claude --attach paper.pdf --reviewers codex,claude --pretty

  3. Or just tell your agent: “use momm to referee this manuscript under the journal's rules in .reviewrules” — it will read the insights first, reproduce what matters, and end with the disposition table.

The coalition

Five minds. Tuned angles. One gate. No blind trust.

Reviewers are read-only diagnostic instruments. Each route ships with a default persona calibrated from the ledger's track record — leaning into what it demonstrably catches and guarded against its measured failure mode. Personas shape the angle, never the schema, and never the rule that findings must be real defects. Override any with --personas.

Evidence, not vibes

Every claim resolves to a hash.

◈Content-addressed reports

sha256 over the stored bytes, bound to the exact reviewed input by its own hash, indexed in a run log that carries the same digests. --store-input is opt-in; by default only the input's hash is kept.

◈Your private ledger

node momm/scripts/ledger.mjs --open renders your own .ensemble_reviews/ into a dashboard with the track record, every transcript, every disposition, and a read-aloud control that speaks structure only — never reviewer prose. Gitignored by protocol; owner-only on POSIX.

◈The public export

This site's Review Studio is a deliberate, separate export of this project's own ledgers: paths normalized, private links removed, digest sidecar re-sealed, and CI refuses the build if a local path slips through.

◈Termination-proof

Every reviewer subprocess runs inside a layered kill chain — tree kill → child-kill backstop → hard deadline → flush-then-exit — so even a kill-restricted sandbox always gets its structured report back. Simplifying it is forbidden by protocol, and the coalition rejected a suggestion to do exactly that.

The dispatcher is a single Node 18+ script with no dependencies, verified by 49 deterministic self-tests, 20 Setup Center tests, 8 ledger tests, and a CI matrix across 3 operating systems × 3 Node versions on every push — including forced-failure drills for evidence persistence and stream purity. Get started

Three commands to a five-model review.

  1. Clone and link into every detected harness (Claude Code, Codex, Gemini, Antigravity — junctions on Windows, symlinks elsewhere):

    git clone https://github.com/marroccofella/skills && cd skills && node install.mjs --target all

  2. Check every route — zero model calls; prints the exact install/login command for anything that's down. Or open the local Setup Center (node momm/scripts/setup-ui.mjs) for guided OAuth onboarding on 127.0.0.1:

    node momm/scripts/multi-review.mjs --preflight --governor claude --pretty

  3. Review your changes — or just tell your agent “use momm”. Your private dashboard is one more command: node momm/scripts/ledger.mjs --open

    git diff HEAD | node momm/scripts/multi-review.mjs --governor claude --pretty

Release gates: add --min-success N so timeouts cannot thin the coalition below quorum. Conventions: a .reviewrules file at the repo root is injected into every reviewer's prompt. Every run confesses its version and checks once a day for a newer release (fail-silent; NO_UPDATE_CHECK=1 disables).

FAQ

Does it send my code anywhere?

Only to the providers you have deliberately logged into, through their official CLIs, for the review you asked for — that is its entire purpose. This website sends nothing anywhere. Setup and preflight never read credential contents; the Setup Center's optional connectivity test speaks one disclosed synthetic sentence.

What if a reviewer is wrong?

Then it fails reproduction and is rejected on the record, and its measured precision falls. The ledger already contains such rejections — the gate protects in both directions.

Which harness can be the governor?

Any of codex, claude, gemini, antigravity, copilot, grok, or “other”. The governor is always excluded from the reviewer pool for that run.

Can I run it in CI?

Yes — --strict and --min-success give non-zero exits, --stream gives NDJSON events on stderr with the report alone on stdout. Reviewers need network access and their OAuth token stores, which restricted sandboxes typically block; the dispatcher documents that case and still returns a structured report.

Is the walkthrough voice real?

It is a synthetic clone of the creator's own voice, generated locally with recorded consent, gated for signal health and word accuracy, and labeled as synthetic wherever it is shared. The repository ships the pipeline as the promptus-clone-voice skill.
